## Promotion Rules

Promote only when at least one is true:

- The same issue repeats at least twice.
- Failure cost is high.
- The improvement can be checked by tests or lint.
- The rule applies across most project work.

## Promotion Paths

- User preference: `docs/preferences/`
- Design reason: ADR
- Repeated failure: test or lint
- Repeated procedure: runbook
- Repeated task: skill candidate
- Repeated external integration: MCP candidate
